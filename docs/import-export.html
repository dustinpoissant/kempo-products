Import and export

Export on the products page downloads the catalog. Import reads a file back, which is also how you move a catalog in from another shop's spreadsheet.

Export

Two kinds of file:

FileHolds
Spreadsheet (.csv)One row per product, with a column for every field. Opens in Excel or Google Sheets.
Everything (.json)Products plus the types and fields they use, to move a catalog to another site.

Images are not exported, because a picture's id means nothing on another site.

Product names that a spreadsheet would run as a formula (starting with =, +, - or @) are written with a leading apostrophe, so they open as text. The apostrophe is removed again on import. A negative price adjustment such as -1.00 is left alone.

Import

Choose a .csv or .json file. The dialog checks it and says what will happen before anything is changed: how many products will be added, how many updated, how many are already there and will be left alone, and which rows could not be read, with their line numbers.

  • Rows are matched to products by slug (made from the name when a row has none), so importing the same file twice never adds anything twice.
  • The default for a product that is already there is to leave it alone. Choose Update it from the file to change it.
  • Rows are independent: one that cannot be read is reported and the rest carry on.
  • In a spreadsheet, an empty cell leaves what a product already has unchanged (and uses the default for a new product). A file with just slug and price columns updates prices and nothing else.
The check before importing. Nothing has changed yet: this says one product would be added, one is already there, and two rows have problems (a missing name, and a type that does not exist).

Spreadsheet columns

Only name is required. Column names are not case sensitive.

ColumnHolds
slugThe product's address. Made from the name when empty
name, description, tagsText. Tags are comma separated
typeA type's name or key. The type must exist already
status, availabilityAs in the admin: published, sold and so on
price, price_labelA decimal such as 49.99. The label shows when there is no price
stockA whole number, or empty for unlimited
optionsThe product's options as JSON, which is what Export writes
field.<key>One column per custom field, for example field.scale

A small file that adds two products:

name,type,status,price,stock,tags,field.scale
Mini Cooper,Model car,published,32.00,4,"british, small",1:18
VW Beetle,Model car,draft,28.50,,classic,1:24

The JSON file

The JSON export has the products, the types and the fields. Importing it creates any type or field the site does not have yet, as things people manage, so a catalog can move from one site to another in one step. A type or field that already exists is left alone, whatever the file says.

For code, the same thing is available from the server SDK:

import { buildExport, importFile } from 'kempo-products/sdk';

const [, file] = await buildExport({ format: 'csv' });    // { filename, contentType, body }
const [, result] = await importFile(text, { onMatch: 'update', dryRun: true });
// { created, updated, skipped, errors: [{ line, name, message }], notes }
