# Changelog

All notable changes to `kempo-products` are documented in this file.

## [Unreleased]

### Added

- The Products admin page has a `products-admin-tabs` location after its tabs, so an extension can add a tab there.

- **Categories can be imported and exported** as a spreadsheet (.csv) or everything (.json), from the Categories tab's top bar. Categories are matched by key, so importing a file twice never duplicates; a category already there is left alone unless the import is set to update it. Dry run first, as for products. Server: `GET /products/api/categories/export`, `POST /products/api/categories/import`, both with `products:categories:manage`.
- **The Categories table has search, filters and the field sort and hide control**, like the Products table.

### Changed

- The Stock Levels tab has a `products-admin-stock-notes` location above the ledger, for an extension to add a note (kempo-products-inventory adds its warning there).

- **`k-products-product-picker`** is a reusable form input for choosing one product. It searches the server as you type, so it works for any number of products, and its value is the product id. Stock Levels uses it in place of a dropdown of every product.
- **Stock Levels** (formerly Ledger) adds entries in a dialog, opened by an Add entry button. The tab says at the top that it is only for products with no linked inventory: a product made from inventory takes its stock from the inventory, and an entry for it is refused.
- **Templates, Attributes and Ledger are tabs on the Products page**, next to Products, Categories and Settings, with hash routing. Their own pages and the toolbar links to them are removed, with no redirects. The tabs need the same permissions as the old pages did.
- **The product and template forms are a context with the tabs on the page.** `k-products-form` and `k-products-template-form` hold the product or template and call no visible UI themselves. One Save above the tabs (`k-products-save-button`) saves the whole product or template at once. Each tab (`k-products-details-tab`, `-description-`, `-media-`, `-template-`, `-attributes-`, `-options-`, `-credits-` and the template's `k-products-template-*-tab`s) is a component on the page with its own Save button, which saves only its fields. The first Save creates the product. The page no longer moves to a list after saving.
- **The attribute `tab` field is removed.** The product form puts admin-added attributes on its Attributes tab and does not take the placement from the data. A migration drops the column. Extension-owned attributes are shown by their extension, on its own tab.
- **The Credits tab is contributed by kempo-credits**, through the `products-admin-product-tabs` location, so it appears only while kempo-credits is installed. The Template tab's Defaults show the attributes an administrator added; kempo-shipping shows its own on its tabs.
- **`k-products-tab` is replaced by a plain `k-tab` and `k-tab-content`** in the `products-admin-product-tabs` location, and the `product-saved` event waits for nothing: a tab saves its own data.

- **The Products toolbar's Import, Export, Ledger, Templates and Attributes are controls** that look like the table's search and filter controls, not grey buttons. New Product stays a primary button. The Categories tab's New category button is in the table's top bar.
- **Products, Categories and Settings are one admin page** at `/admin/extension/kempo-products/`, with a tab for each (hash routing, so each has its own address: `#categories`, `#settings`). The Categories and Settings pages and their nav entries are removed, with no redirects from the old addresses, and the Categories button on the Products toolbar is gone. The Categories tab needs `products:categories:manage` and the Settings tab needs `products:settings:manage`, as the old links did. The Settings sections are no longer boxed and fill the tab's width.
- **The credits rate (`credits_per_unit`) belongs to kempo-credits now**, and is set on its Settings tab. Products reads it from there and falls back to 100 without it. The setting is removed from Product Settings and from `/admin/settings`: kempo-credits' update moves a value kempo-products still holds, and kempo-products' update removes it when kempo-credits is not installed.

### Added (templates)

- **A template can give a product its product type, price, lowest price after discounts, price label, description, tags and categories** (a **Product** tab on the template page). A product that sets one itself keeps its own; one that leaves it blank uses the template's, so a "Model car" template set to Physical Item at $24.99 makes every model car that, until one says otherwise. The product form shows the template's value as the placeholder ("Template: 24.99") or a hint, and the product type has a "The template's (Physical Item)" choice, which a new product starts on. Everything that reads a product (the cart, discounts, the public pages, the price API) sees the value in force; `own` on a product holds only what it was given itself, which is what the form edits and an export writes. A template holds them in `product`. Quantity and status are not inherited, because stock and whether something is for sale belong to each product.
- **The product and template forms keep their save button disabled until what is required is filled in:** a product needs a name and every required attribute that has no value and no default from its template (hover the button to see what is still needed); a template needs a name.
- **A View on site button on the Edit Product page**, opening the product's page in a new tab (a draft or archived product is only visible to people who manage products, and the button says so).
- **Product templates:** a product can be made from a template, and keeps inheriting from it. A template holds **attributes** of its own (a model car's "Scale"), **options** every product made from it offers (Color: black, white), and **default values** for any attribute, including the attributes every product has, so every model car can have the same weight and size without typing it on each one. A product can add its own attributes (`attributeDefs`), its own options, and extra choices to an option its template offers (a template has Color in black and white, this product adds red and blue). A product that leaves an attribute blank shows its template's default, which also counts for filtering and satisfies a required attribute. Make them under **Admin > Products > Templates** (a page with Details, Options, Attributes and a tab for each group of every-product attributes, such as Shipping, with one Save); a product picks one on its **Template** tab. A template that products are made from cannot be deleted. Server SDK: `getTemplates`, `getTemplate`, `createTemplate`, `updateTemplate`, `deleteTemplate`, `registerTemplate(owner, definition)`, `unregisterTemplates(owner)`, `effectiveAttributes(product)`; API `GET/POST templates`, `PATCH/DELETE templates/<key>`; a product has `template`, `attributeDefs`, `inherited`, `ownOptions`; `getProducts({ template })`; events `kempo-products:template:*`. CSV and JSON export and import carry the template of each product (JSON carries the templates themselves). A site that installed earlier gets the `kempoProductTemplate` table and the `template` and `attributeDefs` columns on update.
- **A product's type can now be set through the API:** `productType` was accepted by the server SDK but dropped by the create and update routes.

### Changed (breaking)

- **The permission `products:types:manage` is split in two:** `products:templates:manage` for templates and `products:attributes:manage` for attributes, both in the `kempo-products:admin` group. The update gives both to every group that held the old one, so nobody loses access; the old permission is left in place, because kempo never deletes one.
- **Custom fields are now called attributes**, to match WooCommerce. The admin page is **Products > Attributes**, a product's values are `attributes` (they were `fields`), the fields it adds are `attributeDefs`, and a template's are `attributes`. In code: `getAttributes`, `createAttribute`, `updateAttribute`, `deleteAttribute`, `registerAttribute`, `registerAttributes`, `unregisterAttributes`, `effectiveAttributes`; the API is `/attributes`; the CSV columns are `attribute.<key>`; the events are `kempo-products:attribute:*`; the table is `kempoProductAttribute`. The update renames the table, its index and the columns, keeping every row. Files exported before the rename (with `field.` columns, or `fields` in JSON) still import.

### Removed (breaking)

- **Product types.** The type of a product, its admin pages (Product Types, the type tab), the `/types` API, `getTypes`, `createType`, `updateType`, `deleteType`, `registerType` and `unregisterTypes`, the `kempo-products:type:*` events, the `type` property of a product, the `type` filter of the list, `getProducts` and the export, and the scoping of an attribute to a type (`productType`) are gone. An attribute now belongs to every product. They are to be replaced by templates a product inherits from. A site that installed earlier keeps the old table and columns, which nothing reads; drop `kempoProductType`, `kempoProduct.type` and `kempoProductAttribute.productType` when you no longer want them. The permission `products:types:manage` is replaced by the two below.

### Added

- **A default choice for an option:** pick the **Default choice** of an option and the product page starts on it; the buyer can still pick another. A required option left blank (an API call, an old link) takes its default instead of failing. A choice has `default`, at most one per option.
- **Money attributes:** a `currency` attribute type, stored as whole smallest units and shown in whole currency units with the currency code. A money attribute can become a plain number.
- **Attribute tabs:** an attribute can name a `tab`, and the product form gives it a tab of its own (an attribute with `tab: "shipping"` goes in a Shipping tab instead of under Details). A group and an extension tab with the same name share one tab.
- **Product types:** what kind of product something is, and so how it is delivered. kempo-products alone has one, **Generic Product** (`generic`, nothing is shipped for it), and extensions add more: kempo-shipping adds **Physical Item** (`physical`), kempo-credits adds **Credits Only** (`credits-only`). Extensions register theirs with `registerProductType(owner, { key, name, description, needsShipping })` and remove them with `unregisterProductTypes(owner)`. A product gets its product type from a dropdown in the admin (shown once there is more than one), from `productType` on the API, and `GET /products/api/product-types`. A site that installed earlier has its item types and the `itemType` column renamed to match by the update, and keeps `physical`, which kempo-shipping takes over.
- `creditsOnly` now follows the product type (`credits-only`), so older readers keep working; existing credit packs are moved to `credits-only` by the update.
- **Categories.** A product is of one type and can be in any number of categories, which shoppers browse by. Manage them under **Admin → Products → Product Categories** (new permission `products:categories:manage`, in the `kempo-products:admin` group) and tick them on the product form's **Details** tab. A category has a name, a description and a key made from its name, which never changes, and deleting one takes it off its products and leaves them. A product has `categories` (a list of keys); `getProducts({ category })` and `GET /products/api/products?category=` keep products in every category given; `<k-products-list category="…">`, a Category menu on the list and `/products/?category=` use it; `/categories/` lists the categories that have published products, with how many. The admin product list has a Categories column. CSV and JSON export and import carry them (by key or name; a JSON file brings the categories themselves). Server SDK: `getCategories`, `getCategory`, `createCategory`, `updateCategory`, `deleteCategory`; browser SDK the same; events `kempo-products:category:created`, `updated` and `deleted`. A site that installed earlier gets the `kempoProductCategory` table and the `kempoProduct.categories` column on update.
- **A `/categories/` page**, from a second scope. The extension now answers on two addresses, `/products` (from `public/`) and `/categories` (from the new `public-categories/` folder, declared with `"public-scopes": { "categories": "public-categories" }`). It lists the product categories, each linking to the product list narrowed to it (`/products/?category=…`), through `<k-products-category-list>`. Needs a kempo with multiple scopes. Kempo now refuses to install or enable the extension beside another that claims `/products` or `/categories`.
- **Extensions add to product cards and the product page by composition.** The pages carry the locations `products-scripts`, `products-card-actions`, `products-detail-actions` and `products-detail-extra`, and an extension fills them with a `*.global.html` file in its `public/`. The product list has **one** `<template data-products-card>` (from the `products-card-template` fragment, which a page embedding its own list includes once), cloned into every card. An extension's element finds its card with `closest('k-products-card')` (the `product-id` attribute and the `.product` property) and its product page with `closest('k-products-detail')` (`.product`, `.selections`, `.price`, `.complete`, and its `selection-change` event). Several extensions stack in one location by priority, which a fragment cannot do. See *Adding controls to products*.

- **A price an extension can replace.** The card and the product page each have a `price` slot whose default content is the usual price, so nothing changes until an extension puts its own element there (a sale price with the old one struck through) through the new locations `products-card-price` and `products-detail-price`. The product page exposes `config`, `price` and `money(minor)` for it.

### Changed

- **Contributions name their slot.** The locations are placed directly among a component's children, with no wrapper element, and an element names the slot it fills with `slot="actions"`, `"price"` or `"extra"`. A wrapper would always occupy the slot and hide its default content.
- **`<k-products-card>` carries a `product-id` attribute**, and its `product` property is the product it was given, so a component slotted into it finds both with `closest('k-products-card')`. Its `actions` slot is filled by the list from the page's template (see above) instead of by hand.
- The product page's `actions` and `extra` slots are filled from the `products-detail-actions` and `products-detail-extra` locations, and `<k-products-detail>` exposes `product`, `selections`, `price` and `complete`.
- `registerProductAction` is **deprecated**. It keeps working, and will be removed in a later major release.

### Added (discounts)

- **A minimum price on a product** ("Lowest price after discounts"): `minimumPrice`, the lowest a discount extension may take the unit price to, so stacked sales and old codes cannot sell it at a loss. An attribute on the product form, in the API (`POST` and `PATCH products`), in the `kempoProduct` table (added to existing sites by `install.js`), and in import and export (a `minimum_price` CSV column, which sits after `price_label`). It must be a whole number and not above the price. Nothing in this extension discounts anything; kempo-discounts and kempo-commerce read it.
- **Two places for other extensions to add admin buttons:** the `products-admin-product-actions` location on the product edit and new pages (an element with `slot="actions"` appears beside Save and Cancel) and `products-admin-category-actions` on each category in the category list (one template cloned into a new `<k-products-category-actions>` item per row), with `products-admin-scripts` for their modules. See "Buttons" in the README.

### Changed (breaking)

- **Purchases and holds are gone; there is a ledger.** This extension never took orders, so it no longer pretends to. Every change to a product's quantity is a row in the new `kempoProductLedger` table (what changed, by how much, why, and what was left), shown on a **Ledger** page where you can add stock or take it away. The SDK is `addLedgerEntry({ ref, lines: [{ productId, change }], note, reason, undoes, actor })` (all the lines or none, idempotent by `ref`), `getLedger` and `getLedgerEntry`; `setQuantity`, `adjustQuantity`, creating a product with a quantity and editing one all write to it too. Removed: `recordPurchase`, `reversePurchase`, `getPurchase`, `getPurchases`, `holdQuantity`, `commitHold`, `releaseHold`, `expireHolds`, `getHold`, `getHolds`, `getHeldQuantities`, `grantPurchaseCredits`, the `purchase:*`, `hold:*` and `quantity:take_failed` events (the new ones are `ledger:before_add`, `ledger:added` and `ledger:add_failed`), the `kempoProductPurchase` and `kempoProductHold` tables (existing rows are left in the database, unused), the `purchases` API and the `products:purchases:record` permission (now `products:ledger:add`). Pricing a cart, holding stock while a payment is pending, granting credits and refunds belong to whoever takes the order (kempo-commerce).
- Its menu entry is in the new **Products** group, first (priority 89), instead of Commerce.
- **Custom elements are renamed to `k-products-<name>`**, the extension's name after `k-`; the old tag names stop working: `k-prod-list` is `k-products-list`, `k-prod-card` is `k-products-card`, `k-prod-detail` is `k-products-detail`, `k-prod-form` is `k-products-form`, `k-prod-attribute-input` is `k-products-attribute-input`, `k-prod-attributes` is `k-products-attributes`, `k-prod-images` is `k-products-images`, `k-prod-money` is `k-products-money`, `k-prod-options-editor` is `k-products-options-editor`, `k-prod-widget` is `k-products-widget`, `k-prod-purchases` is `k-products-purchases`, `k-prod-row-action` is `k-products-row-action`, `k-prod-settings` is `k-products-settings`, `k-prod-types` is `k-products-types`. The product form's tab marker `<k-prod-tab>` is `<k-products-tab>` too: an extension that adds a tab (kempo-products-inventory does) must use the new tag, so update them together.
- **"Stock" is now "quantity", everywhere.** A product, a kempo-inventory item and a cart or order line all say `quantity` for how many, so there is one word. The `kempoProduct.stock` column is `quantity` (`install.js` and `update.js` rename it on an existing site, keeping every number); `product.stock` is `product.quantity`; `setStock`/`adjustStock` are `setQuantity`/`adjustQuantity`; `holdStock` is `holdQuantity`; the `kempo-products:product:stock_changed` event is `kempo-products:product:quantity_changed` with `previousQuantity` and `quantity`; the API and the import and export columns say `quantity`. A CSV or JSON file exported before the change still imports, because its `stock` column is read as `quantity`. "In stock" and "out of stock" remain as the plain English they are, and `inStock` is still the yes or no a product reports.

### Added

- **A managed product is managed only while its manager is installed and enabled.** Disabling or uninstalling kempo-products-inventory (or any extension that called `setManagedBy`) hands its products back to people with no clean-up, and enabling it takes them back. Products read from the catalog report `managedBy: ''` when the manager is gone, and a new manager may take over from one that went away.
- **A manager answers ledger entries for its products, and can refuse.** `addLedgerEntry` fires the guard `kempo-products:ledger:before_add` (`{ ref, lines, products, reason, note, undoes, actor }`) when any product is managed; the manager takes what the lines use, or puts back what `undoes` took, and throws `{ code, msg }` to refuse. kempo-products never writes a managed product's quantity itself, and `kempo-products:ledger:add_failed` `{ ref }` tells the manager to undo what it did when the entry then fails.
- **`registerProductAction(tag)`** (`/products/components/actions.js`): an extension registers a custom element and every product card and product page shows one, handed `product` (and on a product page `selections`, `price` and `complete`), so a store can put "Add to cart" on products without editing either page.

- **Credits, when kempo-credits is installed and enabled.** A **Credits** tab on the product form and a **Percentage that can be paid in credits** attribute under the price. A product gives credits when bought (`creditsGranted`), may be a **credit-only item** (`creditsOnly`, which is how credit packs are sold: a pack is a product), and says how much of its price credits may pay (`creditPercent`, 0 by default, 100 for entirely). `recordPurchase` grants the credits once, `reversePurchase` takes back what is held and leaves what was spent as an amount owed, and `getPrice` reports the most credits that may be used. The `credits_per_unit` setting says what a credit is worth. kempo-credits is an optional peer, found with `getExtension` and imported on demand; the new columns are added by `install.js` and `update.js`.
- **A Product Settings page** at `/admin/extension/kempo-products/settings/`, last in the Products group in the admin nav, with the catalog's settings in sections and every value checked before it is saved; `GET`/`PUT /products/api/settings` and the `products:settings:manage` permission (held by `kempo-products:admin`). The table at Admin Settings still edits the same values.
- **Dashboard widget.** A **Products** widget on the kempo admin dashboard showing catalog size and the latest products, with a **New product** button, declared in `widgets` in `kempo-config.json`. Needs a kempo with the dashboard; ignored on older versions.

First release.

A product catalog for kempo that works on its own, with no checkout and no inventory.

### Catalog

- Products with a name, slug, description, status (`draft`, `published`, `archived`), availability (`available`, `pending`, `sold`), an optional price and price label, tags, stock, and pictures.
- **Product types and attributes** an owner builds in the admin with no code: an attribute applies to every product or to one type, in kinds short text, long text, number, yes/no, date, colour, rating, choice list and images. Attributes can be filterable on the public list.
- **Options with relative prices.** A choice adds to or takes from the base price (`-1.00` for no clear coat), or, per option, replaces it. One replacing option per product. The server computes every price; nothing trusts a browser.
- **Stock** as a number, or unlimited by default, so a catalog that never counts never shows "out of stock".
- Optional images through kempo-media, hidden when it is not installed. Lists and cards load the small thumbnail the API supplies (kempo-media's, made by kempo-thumbs) and fall back to the full image while one is not ready; the detail page shows the full image, with thumbnails in its gallery strip.
- Ownership: types, attributes and products can belong to an extension, which alone can delete them or change what defines them.

### Public pages

- `/products/` with search, filters, sorting and paging, all kept in the address.
- `/products/<slug>/` with pictures, the options a buyer chooses (kept in the address, `?color=red`), a server-priced total, and the product's details. Sold-out and invalid choices in the address are ignored.
- The pages are Lit components (`k-prod-list`, `k-prod-card`, `k-prod-detail`) usable on any page. `<k-prod-list>` can be limited to a type, tag, hand-picked slugs, availability, what is in stock or an attribute value, can start sorted or searched, and can show a few products with `limit`, `hide-controls` and `no-url`; see `docs/components.md`.

### Purchases and extension points

- `addLedgerEntry` changes the quantity of every product in an entry or none, is idempotent by `ref`, and fires `kempo-products:ledger:added`. Taking more than a product has is refused.
- `setManagedBy`, `setStock` and `setChoiceAvailability` let an extension keep stock and choice availability in step with something else; people see them read-only.
- Guard and notification hooks for products, types, attributes, quantity and the ledger.
- The admin product form is split into tabs (Details, Description, Media, Options). Another extension adds a tab by pushing a `<k-prod-tab>` into the `products-admin-product-tabs` location from an `admin/*.global.html`, and the form fires `draft-change` and `product-saved` so the tab can save with it.
- The description is edited with the full rich text editor and shown (sanitized) on the product page; plain-text descriptions keep their line breaks.
- In the options editor each choice sits in its own box under its option, so removing an option and removing a choice are no longer easy to confuse.

### Import and export

- Export the catalog as a spreadsheet (`.csv`) or everything (`.json`, including types and attributes). Import either, matching products by slug so a file imported twice never duplicates, with a preview of what will happen and a per-row report of what could not be read. In a spreadsheet an empty cell leaves what a product has unchanged.
- Spreadsheet cells that would be read as formulas are written as text.

### Admin

- Products, Types, Attributes and Ledger pages, built from kempo-ui components. Permissions `products:*` and groups `kempo-products:viewer`, `manager` and `admin`.

## [0.3.1] - 2026-10-26
### Changed
- The admin product list is a kempo-ui table. The product name opens the product, and the view and edit actions are row controls.
- The categories list is a table with Edit before the row and Delete after it. The category sale buttons are row controls: `products-admin-category-actions` now puts its elements in each row with `slot="after"`, and `<k-products-category-actions>` is removed.
- Attributes, templates and the stock ledger are tables. Deleting an attribute or template is a row control.
- Requires kempo 4.9.7 (the admin lists use kempo-ui tables).
