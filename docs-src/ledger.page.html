Every change to a product's quantity is written to the ledger: when, who, by how much, why, and what was left. This extension does not take orders, hold stock for a payment, give credits or reverse anything. Whoever does adds an entry to the ledger, and products changes the quantities.

Adding an entry

import { addLedgerEntry } from 'kempo-products/sdk';

const [error, entry] = await addLedgerEntry({
  ref: 'order-1042',
  reason: 'sale',
  lines: [
    { productId: '9f2c1e0a44b7d3a1', change: -2 },
    { productId: '51b7c0d9e8a2f364', change: -1 },
  ],
});
  • A line's change is how much to add. Negative takes away. A sale takes, a delivery or a return adds.
  • Every line or none. If any product has too little, nothing changes and the error says which one (409). Quantity never goes below zero. Two lines for one product share that product's quantity.
  • ref is the caller's own reference and is optional. Adding an entry with a ref that is already in the ledger changes nothing and returns the first one with duplicate: true, so a retry can never change the quantity twice.
  • reason (a short word such as sale, return or count) and note (free text) are shown on the ledger.
  • A product with unlimited quantity is never changed and gets no row.

Then kempo-products:ledger:added fires with the entry, and kempo-products:product:quantity_changed for each product. Nothing a listener does can undo the entry.

Putting back what an entry took

There is no reverse. A cancelled order is another entry that adds the same quantities back. Say which entry it puts back with undoes, which is what lets the extension that maintains a product's quantity return exactly what it took:

await addLedgerEntry({
  ref: 'order-1042:cancelled',
  undoes: 'order-1042',
  reason: 'return',
  lines: [{ productId: '9f2c1e0a44b7d3a1', change: 2 }],
});

Reading it

getLedger({ productId, limit, offset }) returns { items, total }, newest first, and getLedgerEntry(ref) returns one entry. Each row keeps the product's name, so it still reads correctly after the product is deleted.

Changing a quantity any other way is in the ledger too: setQuantity, adjustQuantity, creating a product with a quantity, and editing the quantity on a product in the admin. So the ledger adds up.

In the admin

The Ledger button on the Products page opens the ledger. A person with the products:ledger:add permission can add stock to a product or take it away there, for a delivery, a count, or a sale made on Etsy or in person.

Managed quantity

An extension that keeps a product's quantity in step with something else, such as inventory, declares that, and people then see the quantity and which choices are in stock as read-only, with the extension's name:

import { setManagedBy, setQuantity, setChoiceAvailability } from 'kempo-products/sdk';

await setManagedBy(productId, 'my-extension');
await setQuantity(productId, 7, { actor: 'my-extension' });
await setChoiceAvailability(productId, 'color', 'red', false, { actor: 'my-extension' });

Anyone else who tries to change a managed product's quantity, through the admin or the SDK, is refused. Pass '' to setManagedBy to hand it back to people.

The lock lasts only while the managing extension is installed and enabled: disable or uninstall it and its products are people's again, and enabling it takes them back.

A managed product's quantity is never written by kempo-products. addLedgerEntry first fires kempo-products:ledger:before_add with { ref, lines, products, reason, note, undoes, actor }; the manager takes what the lines use (or puts back what undoes took) and throws { code, msg } when it cannot, which refuses the entry with that message. If the entry then fails, kempo-products:ledger:add_failed { ref } tells the manager to undo what it did.
